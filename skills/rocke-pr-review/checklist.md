# rocKE PR Review Checklist

A scannable per-PR checklist of rocKE-specific invariants that generic and AI reviews miss.
Run a generic/AI review first; this covers what those miss.
`★` = high-importance. Each item names the PR where the lesson was learned.

> **Context that changes how you grade (read first):**
> - **Re-run this checklist on the REVIEW-RESPONSE diff, not only the original.** Fixes written to satisfy a comment arrive late, feel small, and routinely skip the gate. (#12070/#12090: all nine reviewer catches across both PRs were in code added to answer a review — the `ctrl` guard, the profiler, the hoisted helper and their tests.)
> - **C++ is LIVE.** The C++ attention path is no longer dormant — a C++/Python divergence is a real break, not latent.
> - **Full parity across THREE stages is the target.** Cross-engine parity spans **problem→spec** (selector/spec-builder, checked by `prove_parity_binding.py`), **spec→DSL** (builder, `run_diff.py` `ir`), and **DSL→`.ll`** (lowering, `run_diff.py` `ll`). Attention has a real C++ builder (`rocke_build_unified_attention_2d_tiled_scalar`); it lags today (tech debt) but must be resynced going forward — Python-only is the current lag, not an exemption.

## A. Byte-identity & two-engine parity
- [ ] Kernel-body emitters need no C++ twin only where the family is Python-only; where a C++ kernel twin exists (GEMM/conv — and attention's lagging builder), keep it in sync.
- [ ] Core lowering-op / op-handler changes (`core/lower_*`, `core/ir`) mirrored in both engines — even when the PR's kernels are Python-only.
- [ ] Selectors, spec builder, lowering, dispatch, knobs (the layers on top) mirrored in C++ — unconditional.
- [ ] Where a C++ twin exists, its emit ORDER matches Python exactly (cmp operand order, `land` nesting, site order) — verify, don't assume.
- [ ] Representative-IR golden UNCHANGED for byte-identical changes; re-blessed only for an intentional IR change. (It guards identity, not perf; representative shapes only; covers NO attention.)
- [ ] "Golden untouched/added" is NOT parity proof — ask WHICH gate (Python-drift golden vs cross-engine `check_byte_identity.py`).
- [ ] New logic guarded so covered shapes emit identical IR; no unconditional op on a hot path.
- [ ] Don't trust green CI for C++ — it often isn't built; review C++ by hand / run `check_byte_identity.py`.
- [ ] Shared op-handler fix proven cheaply via a `<op>_emit.{py,c}` mini-pair in `library/tests/parity/`.

## B. Coverage & silent-fallback
- [ ] Every new rejection/gate classified: real hardware limit vs implementation shortcut (shortcut → `NOT_YET_IMPLEMENTED` + backlog, not a permanent contract).
- [ ] Preflight gate rejects EXACTLY what the spec constructor rejects, per arch.
- [ ] No real model-zoo shape silently demoted to the slow fallback; fallbacks are loud/measured.
- [ ] ★ At a trust boundary, REJECT — never NORMALIZE into validity. Masking (`& 0xFF`), clamping, coercion or `getattr(x, field, default)` on a meaningful field rewrites malformed input into DIFFERENT valid input, turning a loud failure into a silent wrong answer. Name what each such expression rewrites and what the caller gets instead; validate at the LAST gate before the value is consumed (the lowerer, not only the builder) — IR/requests also arrive deserialized, rewritten by a pass, or hand-built. A refactor must preserve FAILURE modes, not just success paths. (#12070: `ctrl=256`→`0` = lane-0 broadcast; #12090: a hoist's `getattr(..., "auto")` made a request missing `algorithm` match every candidate instead of raising.)
- [ ] Gate scope = verified scope — configs newly opened by a gate are tested or scoped down.
- [ ] `is_valid_spec`/`supports_*` is FUNCTIONAL-only — reject only emit-impossible/undefined configs (tile/atom geometry, LDS/regs, missing MmaOp/dtype/arch, incompatible flags, no-safe-IR boundary); perf/policy/coverage/routing opinions live in dispatch, and `reason` names the hardware/algorithm invariant, not the workload. (`dnn-providers/hip-kernel-provider/rocke/platform/dsl_docs/architecture/authoring_model.md` §2; PR #10422)

## C. DRY / single-source / blast-radius
- [ ] Repeated predicate/logic → one named helper (missed-site = silent bug).
- [ ] One `build_<family>(spec)` per family — no bespoke shape-class kernel (no `build_attention_sq8192.py`, no in-body `seqlen`/`M-N-K` branch); shape-specific logic → spec flag or dispatch; harnesses call the public `build_*`/`run_*_torch`, never fork IR. (`dnn-providers/hip-kernel-provider/rocke/platform/dsl_docs/architecture/authoring_model.md` §1; PR #10422)
- [ ] Name by operation+algorithm, not workload — `build_unified_attention_2d_tiled` good; `build_attention_d128_sq4096` / `_..._d256_lean` bad. `kernel_name()` MAY carry codegen knobs (dtype/head_size/block_n/tile-warp/ragged/persistent) but NEVER workload sizes (batch/seqlen/M-N-K/model) — those are `b.param` runtime args. Pin a one-shape body via a named constant classified validation-gate vs algorithmic-limit (§B). (`dnn-providers/hip-kernel-provider/rocke/platform/dsl_docs/architecture/authoring_model.md` §1; PR #10860/#10422)
- [ ] Arch-independent logic lives in `common/`, not forked per gfx942/gfx950.
- [ ] Blast radius judged: inherent fan-out (engines × arches × stages) vs inflated diff (unrelated files) → split the inflation.
- [ ] ★ Make the change easy, then make the easy change — refactor-first (byte-identical no-op) rather than an ad-hoc monkey-patch; design for the next maintainer.
- [ ] Big cleanups welcomed as proven no-ops (golden/parity unchanged).
- [ ] ★ A found bug is a CLASS, not an instance — before calling it fixed, grep every sibling site for the same anti-pattern: the C++ twin, the other arch's helper, and any other code deciding the same invariant. (#10640: a stale `block_size>=32` proxy for the derived `block_m<=tile_size` guard lived in the Python selector, its C++ twin, AND the `_gfx942_bf16_wide_geometry` helper — fixing one left two latent.)
- [ ] ★ WIDENING a shared structure is a CLASS too (the dual of the rule above) — adding a member to a gate SET, putting a change INSIDE a branch every member takes, or introducing a NEW source of truth read by ONE field of a multi-field object reaches **every** member / sibling field / consumer, in code AND prose, **inside AND outside the diff**. Name what the change does to each; a member you can't name is one you didn't check. Grep repo-wide for consumers of the widened symbol — touched-precedent-files is not enough. (#10583: a gfx950 compute-unit floor placed in the shared `_AUTO_RESOLVE_ARCHS` branch silently rerouted **gfx942** partitions; the set's own comment documented only half the coupling; `num_segments` became the lone spec field on a new arch source while the spec class stayed on the running box; and `hip_module.py`'s "gfx942-only caller" docstring — a file the diff never touched — went stale. Four reviewer catches, one class.)

## D. Dispatcher & spec integration
- [ ] ★ Knobs/features on the `KernelSpec` (validator + selector + name tag + cache-key), NOT `os.environ` (env only as a selector-level diagnostic override folded onto the spec). Reviewers may reject env vars **outright — even a reproducibility/pin one** (#9739: *"please dont use env variables"*, on a `ROCKE_NUM_SMS` pin that WAS folded onto the spec); pin via an explicit spec field / caller value, not `os.environ`. Treat "env as diagnostic override" as risky, not a safe default.
- [ ] Derived cache-key faithful to what's built — key on the override predicate (one bit), not duplicated flags.
- [ ] Cohort routing keeps spec-builder + launch-meta + cache-key in agreement.
- [ ] Hand-pinned overrides live ABOVE the machine-regenerable heuristics (heuristics → override → resolver).
- [ ] Cohort = single source of truth shared by `supports()` and the spec override predicate.
- [ ] New kernel/arch registered as a `KernelCandidate` AND exercised THROUGH the dispatcher by a harness (not a hand-built spec).
- [ ] CPU routing test: selects the cohort candidate, outranks generic, force-by-algorithm, rejects out-of-cohort.
- [ ] Don't over-claim registration — prod `run_unified_attention_torch` still skips the Python dispatcher.
- [ ] Selection-layer fix mirrored in C++ (shipped provider consumes C++ selectors) — now a LIVE break.
- [ ] Fix the chooser, not the artifact — change which spec is selected, not the emitter.

## E. Structure & hygiene
- [ ] `platform ← library` one-way dependency; platform tests don't import library.
- [ ] Library doesn't `import torch` for device queries — use `rocke.runtime.hip_module` (prefer `hipDeviceGetAttribute`).
- [ ] No Jira/tracking IDs, reviewer usernames/GitHub handles, or PR numbers in code (comments, docstrings, strings, kernel names, tests). Use a descriptive reference; tracker + commit message + PR description only.
- [ ] Scope discipline — unrelated fixes in their own PR.
- [ ] Only deliverable source committed (no scratch/design `.md`, minimal bench churn).
- [ ] Both arches actually covered, or explicitly scoped out.
- [ ] Dead code removed **or a concept RENAMED** = symbol AND every stale reference (comments/docstrings/flags, **test FILENAMES**, prose naming the old term) in the same commit. `git grep <old_term>` returns zero — grep PATHS too, not just contents. (#10583: `num_sms`→`num_cus` renamed throughout, test shipped as `test_num_sms_resolver.py`.)
- [ ] No dead parameters — and a parameter ACCEPTED then IGNORED is worse than one absent: the caller believes it was used, and in measurement code it silently discards a real observation. Grep each parameter name in the body. (#12070: `substitute_share(total_armA_us=…)` never read it — the measured input could change tenfold without moving the reported share.)
- [ ] Severity honesty — Critical / Warning / Suggestion, stated; don't soften a blocker.
- [ ] ★ Perf evidence follows `platform/AGENTS.md` §Compliance. **No absolute software-achieved numbers** (latency, throughput, TFLOP/s, MFU, bandwidth) in any public artifact — they live only in an approved, access-controlled internal record. **Relative results** (ratios, % changes, including vs AITER) appear ONLY in the PR description or a qualifying benchmark/result doc, and only when every compared arm passed an on-silicon numeric gate in the same run and the claim states its scope (workload and axes, baseline and version, hardware target as a gfx name, method, provenance, caveats) in bounded wording ("faster at these measured configurations"), never a general superiority claim. Code comments and commit messages stay qualitative. A verbal or chat approval does not override this. (#10832.)

## F. Merge-readiness / PR-bot policy (`policy.yml`, not the workflow yml)
- [ ] Branch name matches a recognized prefix (`users/<user>/…`, …).
- [ ] ★ rocKE (hip-kernel-provider) PR branch uses a `rocke` segment (`users/<user>/rocke/<desc>`), NOT `ck`. A `/ck/` branch name triggers Composable Kernel CI (Jenkins "Composable Kernel" multibranch + Math-CI) on a non-CK change — wasted CI + noise. Use `ck` only for actual `projects/composablekernel/` PRs. (#10832 shipped on `/ck/` → recreated as #10885 on `/rocke/`; fix = new-SHA branch, since CK statuses bind to the commit SHA.)
- [ ] Title Conventional Commits `type(scope): desc`, 10–80 chars, scope `[a-z0-9-]+` — NO slash.
- [ ] Description ≥30 chars + an issue reference.
- [ ] A unit-test file in the diff for any changed code file (basename `test_*`/`*_test.*`, any folder).
- [ ] No forbidden files (keys/certs/secrets).
- [ ] `pre-commit` green locally before push (black reformats the whole file).
- [ ] Stacked PR on a feature branch → bot never runs; "no red check" ≠ compliant — self-check `policy.yml`.
- [ ] Don't split/trim for a PR-size cap — it isn't enforced.
- [ ] Don't add throwaway tests just to green the bot; keep only real tests.
- [ ] Verify the PR body/title ACTUALLY took via the API field (`gh api repos/<o>/<r>/pulls/<n> --jq .body` / `gh pr view --json body,title`), not the exit code or web reader — `gh pr edit` can silently drop the body on the classic-projects GraphQL error; set it with `gh api --method PATCH … -F body=@file`. (#10832: title stuck, body silently unchanged; caught only by reading the field.)

## G. Verification honesty (green ≠ correct)
- [ ] Byte-identity proves parity, never correctness — both engines can emit the same wrong output.
- [ ] ★ On-silicon (fp32 ref, bf16 tol) is the only "done" for kernel work; host/compile/CI is necessary, not sufficient.
- [ ] ★ Local non-GPU gate sweep green — or provably unchanged vs `develop`: `check_byte_identity.py` (Python↔C++ IR parity, all families), the installed-golden IR gate (`tests/rocke_installed_golden_test.py`), and the `platform/tests` pytest suite. A red is excused ONLY if shown PRE-EXISTING on `develop` (baseline-diff), never assumed; re-run after each rebase until merge (develop moves). Env traps that masquerade as a "runtime error": byte-identity needs cmake + clang++ (run where they are installed, not on a bare login node); the runtime venv may lack pytest (use an interpreter that has it); the golden harness needs `PYTHONPATH="python:tests/instances"` run from `platform/`; ~7 `test_datalayout_matches_hipcc_emitted_ir` failures from hipcc LLVM-flavor drift are pre-existing on `develop`. (Team directive 2026-07-31.)
- [ ] New behavior has a test that would FAIL before the change (no substring/whitespace-only coverage theater).
- [ ] Ask of every test: what SINGLE code change makes this fail? If none, the property is enforced upstream by a constructor/registrar/validator — test THAT and delete the enumeration; a test that cannot fail hides the day the enforcer is removed (#12090: enumerating registered candidates to assert a family match `CandidateRegistry.register` already rejects). And falsifiability ≠ REACHABILITY — a test can fail-before-pass-after and still construct an input production can never produce, because it enters BELOW the gate that would reject it. For any test entering at an internal function, say how the input gets there through the shipped path, or scope the docstring to "defence in depth, not a reachable input" AND pin the rejecting gate with its own test. (#10583: a mixed-case-arch test drove `_problem` directly while `_request_errors`→`ArchTarget.from_gfx` rejects mixed case first — the docstring claimed a dispatch-path guarantee the request layer never made.)
- [ ] ★ Every load-bearing PROSE claim maps to a check that would FAIL if it were false — **numeric AND structural**. Numbers: identical across code / docstring / README / commit and matching the measurement; a "numerically identical / unchanged / bit-identical" claim needs an A/B that can actually distinguish the arms (a loose fp32-oracle tolerance cannot); a "why the old number was wrong" claim needs evidence (git history / re-measure), never an invented cause; the exact config the PR flips must appear by name in the numeric cohort; a figure stated two ways ("VGPR-neutral" vs "lower VGPR") is a FAIL. **Control-flow claims in CODE COMMENTS are load-bearing prose too** — a comment describing branches, carve-outs, fall-through or "handled later" must match the code beside it; read the branch, don't trust the sentence. (#10885: reviewer caught ~10 numeric gaps — stale holdout prose in ~6 places, an "identical" claim no test could distinguish, a fabricated schedule-change cause, contradictory VGPR wording — all around a functional change that was itself correct. #10583: a gfx950 clamp comment promised "cases … are uncapped later" beside a branch that clamps unconditionally with no fall-through — the sentence described the *gfx942* branch's structure, pasted across.)
- [ ] In a design doc, the fp32 parity reference (the oracle) is reviewed as a first-class gate.
- [ ] No silent dtype fallback (fp8→fp16) in harnesses — loud-reject/skip.
- [ ] Load-bearing numbers (LDS/occupancy) tool-sourced (comgr verbose), not hand-derived.
- [ ] Perf provenance locked: label the device, ratio is the headline, µs device-specific, run the shipped script + parity assert.
- [ ] ★ Optimized kernel is REACHABLE for the shape on the surface that runs it (Python routing proxy AND live C++ selectors), and measured on a real path — NOT a hardcoded bench spec.
- [ ] Two-engine/cross-layer gap graded by who-calls-it-now (grep callers, confirm engine built).
- [ ] Intrinsic overload class verified in the `.td` before recommending a mangled symbol.
- [ ] Bottleneck classified with DYNAMIC hw counters, never static analysis.
- [ ] Wrong-branch risk → read PR content from the commit object (`git show <sha>:<path>`).
- [ ] Plan assumptions verified against the codebase (grep before planning around a symbol).
- [ ] Shipped scripts run once end-to-end, not just `ast.parse`.
- [ ] ★ A guard must be able to FAIL for the reason it NAMES — construct the condition it claims to detect and prove it fires, then name the shape it would MISS and put that blind spot in its docstring. A statistic computed across units RESET between them cannot see a fault recurring identically within each unit. Wire the verdict into what it is meant to stop (a guard nothing reads is decoration), and pair the false-negative probe with a FALSE-POSITIVE rate on a case where the fault provably cannot occur. A one-shot statistic inherits machine jitter — take a minimum over reps and state the residual rate. (#12070: the back-pressure check compared chunk means while the queue was drained between chunks — flat series, ratio ~1.0, every launch blocking.)
- [ ] A gate's FIXTURE must be able to express the failure — ask what input shape would have
      to exist for this check to catch the bug it names, then confirm the fixture produces it
      (a pool with no spare pages cannot show a misplaced write). Widening the fixture is half
      a fix: every gate with its OWN inline comparison needs the check added separately.
- [ ] A ban on CLAIMS needs a sweep over WORDS, not digits — `percent`, `measured on`,
      `ranked`, `faster`, `variation`, not just `\d%`. A detector narrower than the rule it
      enforces returns a clean bill it cannot justify.
- [ ] Measurement code is a DELIVERABLE — every accepted input reaches the output, each derived quantity says MEASURED vs MODELLED, a gate statistic states its false-positive behaviour, and a tolerance is written so it does not get STRICTER as the measurement gets better. (#12070: a residual judged against the run's own noise floor alone failed a 0.1%-of-remainder residual on a very quiet run.)
- [ ] **A skip is not a pass** — a harness that skips when a dependency (e.g. the C++ engine binding) isn't built reports green *without running*; confirm the check actually executed in an environment where the target is built.
- [ ] ★ Perf/routing claims are config-labeled — enumerate EVERY axis the speedup varies with (block_size, Sq, batch, KV-len, dtype), name the SENSITIVE one, state honest caveats (e.g. prod config unconfirmed); a bare "~Nx" invites "which config?". A routing A/B gates BOTH routes vs the fp32 oracle and reports ABSOLUTES, not just the ratio.
- [ ] A golden re-bless is NOT a correctness claim — it proves the IR changed AND flips CI green (removing the tripwire): attribute the move (stash your change / clean-develop worktree / original pre-rebase branch), classify leak-vs-intended by gate-checking each added line, then GPU-re-validate the re-blessed shapes + hold a merge-block.
- [ ] ★ Benchmark on a worktree off the PR's TARGET base — a same-named kernel/builder can DIFFER across branches; confirm kernel-source parity (diff the builder, or compare kernel-name + VGPR/scratch) between where you measured and where you'll merge. (#10832/D256: the campaign-branch 4-warp kernel that "beat AITER" — 475-line, double-buffered, 40 B spill — is a DIFFERENT kernel from develop's 245-line / 528–792 B one; the headline win did NOT exist on the target base. Caught pre-commit.)
- [ ] ★ A/B toggles EXACTLY the knob the PR ships — don't attribute a bundled result. (#10832: exp2-only vs exp2+iglp — iglp helped only the default grid and REGRESSED fp16 default; shipping exp2 alone.)
- [ ] Separate develop→PR delta from a counterfactual — a config the PR leaves byte-identical (fp16/D64 already on the lever) is **0-delta**; a forced-off arm that neither develop nor the PR ships is a counterfactual, never tabled as "without/with".
- [ ] Guarded→fast primitive swap (e.g. `exp2`→`exp2_fast`) only where the precondition provably holds (softmax `x−m_new ≤ 0`; NOT MoE SiLU `exp2(−log2e·g)`, g any sign).
- [ ] No-spill = read the CODE OBJECT, not the clock — `llvm-readelf --notes` (`.private_segment_fixed_size` / `.vgpr_count`) or rocprofv3, on the SHIPPING build; report scratch=0 or "reduced, not increased". A speedup never proves it.
- [ ] ★ Verify the BASELINE, not just the after — prove the defect is real in the SHIPPED code and wasn't MANUFACTURED by another choice in the same PR. A/B the fix against the actually-shipped before-state (not a variant your change introduced), and reconcile any recorded "before" number against reality (git history / re-measure) before trusting it. Distinct from the counterfactual-arm rule (G, "forced-off arm neither ships"): there the strawman is a non-shipped toggle; here the strawman is a defect your own design decision created and then "fixed". (#10845: the "32-way bank conflict" the swizzle removed was created by the same PR's over-wide pow2-128 V row — develop was 4-way; the honest develop→shipped win was far smaller than the headline the manufactured baseline implied. Corollary: derive a pad/width/mask from the bank geometry and prove the MINIMUM — an inherited or over-large constant both wastes the resource and can invent the conflict it claims to fix.)
- [ ] ★ Every measured number carries REPRODUCIBLE provenance — gfx target, toolchain/LLVM flavor, method, harness path — and you re-confirm the COMPILE/RUN TARGET before believing it: a probe built for the wrong gfx arch returns a CONFIDENT wrong number, not a crash (the arch-target axis the device-label / code-object / target-base items don't cover). If a figure surprises you, suspect a wrong-target measurement FIRST. (#10845/exp2: a plausible VGPR-pressure / spill reading was reproduced purely by compiling for the wrong target — the same class of error that seeded the stale holdout figures.)
- [ ] ★ DIFFERENTIAL-TABLE a changed pure decision function — don't read it. A resolver / heuristic / predicate that is a pure function of a few scalars (`_resolve_num_cus`, `select_path`, `_num_segments`, spec builders) is CPU-only: **evaluate it on BOTH checkouts across its input domain**, explicitly including values for arches / partitions / inputs the PR does NOT name, then push the diverging rows downstream through the consumers (routing, segment count, cache key, spec class) and table those too. Attach the table. Reading the diff cannot produce it; running it needs no insight. (#10583: every substantive reviewer catch our reading-based verifier missed arrived this way — the resolver's output unchanged on develop but raised to the floor on the PR, then 2 shapes flipping 2D→3D and 2 doubling segments on an arch the title never mentioned.)

## H. Kernel input validation & memory safety (paged / indirection)
> **Trace, don't scan.** For EVERY device-side mask or bound, write down `(source of its extent)` vs `(the compile-time range the kernel actually visits)` and confirm they agree — or that the gap is masked out of the math. Then grep EVERY launch input that feeds a device bound/mask (`block_tables`, `kv_lens`, strides, counts) and confirm each has a host-validation AND a negative test. A found check on one input is a prompt to check its siblings (§C: a bug is a CLASS).
- [ ] ★ A hardware/resource bound derived from SPEC fields (e.g. an AMDGPU buffer-SRD `num_records` sized from `num_kv_blocks*block_size*num_kv_heads*head_size`) MUST be matched by the launch tensors — host-validate their shape/size against the spec that sizes the bound BEFORE compile/launch, else the bound over-reaches the real allocation and the HW bounds-check stops preventing OOB. Metadata checks (`.shape`/`.stride`) are sync-free; a CONTENTS check forces a device→host sync — gate it behind a flag (default-on; off-able on the hot / graph-captured path).
- [ ] ★ Guard indirection VALUES, not just indices — a masked/bounds-guarded table read protects the lookup INDEX (e.g. logical page `< n_pages`), NOT the value it returns. Any value used as a memory index (block-table physical id) must itself be range-checked, or shown contained by a HW bounds-check — noting that containment is silent-wrong (reads 0), not loud, and is LOST when the per-block offset folds into a 64-bit base (i64) that bypasses `num_records`.
- [ ] Hot-loop `div`/`mod` by a compile-time constant lowers to shift/mask ONLY when the constant is a power of two (else a magic-number mul+shift). AMDGPU has no integer-divide so it is never a runtime divide, but enforce power-of-two in the spec (production page/tile sizes are 16/32) or benchmark the arbitrary-divisor overhead — don't leave it implicit.
- [ ] ★ A device-side MASK/BOUND built from a RUNTIME input (`kv_lens`, `cu_seqlens`, an actual length) MUST cover the FULL compile-time-visited range (every tile the kernel loops over from the constant `Skv`/`BN`). If the runtime extent can be shorter than the compile-time loop, the uncovered region silently takes the masked DEFAULT (0 / page-0) and is folded into the softmax = **wrong output, not OOB** — no fault, no golden-diff, so CI *and* byte-identity both stay green. Host-validate the runtime input against the compile-time constant (e.g. `kv_lens[i] == seqlen_kv`), or prove the softmax masks the gap. [#10572: page-mask extent from runtime `kv_lens` vs the kernel's compile-time `Skv` tiles — reviewer-caught, checklist-missed because H2 was applied only to the block-id VALUE, not this sibling.]
- [ ] Every launch input that feeds a device-side bound/mask has BOTH a host-validation and a NEGATIVE test; an asymmetry (one input guarded, a sibling not) is the tell.

## I. Reusable design principles (apply throughout)
- [ ] Measure the space, not just the selection — best-achievable − shipped gap IS the routing bug.
- [ ] Repair > loud-reject > silent-slow > cryptic-fail.
- [ ] Coverage = union(curated, generated); the rest is a blind spot closed upstream by hypothesis.
- [ ] Keep both "shipped" and "achievable" columns — the delta says faster-kernel vs better-routing.
- [ ] A baked search result is a snapshot that drifts — be explicit snapshot vs live; keep a regen path.

## J. Design & algorithm documents (specs, `ALGORITHM.md`, `DESIGN.md`)
> **A design doc is a reviewable artifact, not a README.** Its equations, symbols, constants and novelty claims can be *false*, and most are mechanically checkable. A docs-only diff is the one shape where an A–I pass grades `N/A` almost everywhere and returns green having verified nothing — so on a Markdown-only PR this section is the review. (#11807: ten reviewer catches, zero from our gate.)
- [ ] ★ TYPE-CHECK every equation — read the operand shapes off the doc's own annotations and confirm inner dimensions match and the result shape equals the declared one. Orientation (`DV × DK` vs `DK × DV`) is declared ONCE in the notation table and every section obeys it; where a sibling doc differs, state the mapping (`S_kda = Sᵀ`) at the boundary. Beware `DK == DV` in the shipping config — it makes a wrong orientation read as the right shape. (#11807 r3975876924: §5 silently adopted `kda/ALGORITHM.md`'s convention; r3975879718: `Diag(dec)` (`DK × DK`) left-multiplying an `EV × DK` state — transposing reverses factor order, so the decay multiplies from the RIGHT.)
- [ ] ★ One symbol, one meaning — every symbol in a formula is in the notation table; a quantity living in two domains (decay vs log-decay) gets a distinct symbol per domain plus the bridge (`decay = exp(gate)`), and a section changing domain says so in the same sentence. A range quoted in a different domain from where it was introduced reads as a contradiction. Check the LOG BASE against the doc you map to (`exp(Gc − Gref)` ⇒ natural log; base-2 is the hardware `exp2` detail). (#11807 r3975900792, r3975918258.)
- [ ] ★ Don't restate an algorithm another doc owns — link and state only the DELTA. Two docs describing one algorithm drift, silently, because neither is executable; the reuse ARGUMENT is the content, the machine's derivation is not. (#11807 r3975887752: §5.1/§5.2 restated `kda/ALGORITHM.md:17-54` near-verbatim, and that copy is where the `S` orientation flipped.)
- [ ] Novelty claims checked against `develop`, not memory — every "added for X / now shared / newly introduced" names a symbol; `git show origin/develop:<path>` decides.
